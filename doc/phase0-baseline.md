## Scope and source revision

- Integration branch: `rework/v2`
- Phase branch: `phase/0-golden-tests`
- Baseline revision and `v1.2.0` tag: `db62e4b11ec541cf940d2b2ef449408199aef0f9`
- `src/main.rs`, `Cargo.toml`, and `Cargo.lock` are unchanged in this phase.
- Golden tests cover behavior that the v1.2.0 implementation already produces correctly. Defect cases are left for their fixing phase.

## Golden CLI cases

`tests/golden_cli.rs` synthesizes inputs in Rust, runs the CLI, normalizes only the temporary file path, and compares the complete stdout including line breaks.

| Case | Coverage |
|---|---|
| A1111 PNG | `parameters` in the first `tEXt` chunk |
| ComfyUI PNG | workflow after IDAT, with the existing 64 KiB first-IDAT fingerprint and tail-scan notice |
| NovelAI PNG | `Comment` JSON pretty-printing and key order |
| JPEG | EXIF UserComment in a little-endian TIFF APP1 segment |
| WebP | XMP `parameters` attribute form currently recognized by v1.2.0 |

The PNGs include valid chunk CRCs and image data. The JPEG and WebP cases contain image data along with their metadata. Temporary test fixtures are removed after each test.

## Performance measurements

Generated by `scripts/phase0_benchmark.py`, using only Python's standard library. Run with:

```sh
python3 scripts/phase0_benchmark.py --binary target/release/fast_meta --iterations 15 --warmups 3
```

The script regenerates fixtures under ignored `target/phase0-fixtures/`, discards stdout and stderr, times the whole CLI process with `perf_counter_ns`, and records the median of 15 runs after 3 warmups. This is the hyperfine-equivalent measurement used here. Fixture generation is deterministic.

| Fixture | File size | Median |
|---|---:|---:|
| ComfyUI PNG, 10,449,686-byte IDAT plus trailing workflow | 10,449,804 bytes | 4.905 ms |
| Stealth PNG, 2048×2048 RGBA, 450 KiB text payload | 85,578 bytes | 48.907 ms |
| JPEG, 5 MiB with EXIF UserComment (APP2 padding before SOS; now the stress case) | 5,242,880 bytes | 4.039 ms |
| PNG without metadata, many 4 KiB IDAT chunks | 2,367,759 bytes | 13.532 ms |
| PNG without metadata, browser-canvas-style RGBA | 136,182 bytes | 10.670 ms |
| PNG without metadata, one large photo-style IDAT | 3,147,775 bytes | 16.489 ms |

The Stealth fixture is non-interlaced (`IHDR` interlace method 0), matching the supported v1.2.0 path. No Adam7 behavior is added or treated as a defect. The current implementation does not expose Negative-First Stage B/Stage C counters, so these baseline timings are end-to-end CLI measurements and do not claim a stage classification.

Raw timings and fixture sizes are also emitted to `target/phase0-fixtures/phase0-results.json` for this run. The generated binary fixtures remain outside version control; the generator is committed so the measurements can be reproduced.

## Phase 5: JPEG fixture alignment and remeasurement

The original 5 MiB JPEG generator reached its target size by placing roughly 80 APP2 segments before SOS. That is useful as a segment-walk stress case, but not as the routine JPEG performance case described in §11.4. The generator now places the 5 MiB scan after SOS for the routine case and retains the original APP2-before-SOS layout as a separate stress fixture. No JPEG parsing behavior was relaxed; the parser still walks every SOS-preceding segment.

Both binaries were remeasured with the updated deterministic fixtures using the same command and output directory. The v1.2.0 binary and Phase 5 binary were both stored in `/tmp`; fixtures were generated under `target/phase0-fixtures` on the same WSL `/mnt/c` volume. Each run used 3 warmups and 15 samples, with the median whole-process time reported.

```sh
python3 scripts/phase0_benchmark.py --binary /tmp/fast_meta-v1.2.0 --output-dir target/phase0-fixtures --iterations 15 --warmups 3
python3 scripts/phase0_benchmark.py --binary /tmp/fast_meta-phase5 --output-dir target/phase0-fixtures --iterations 15 --warmups 3
```

| Updated fixture | v1.2.0 | Phase 5 | Change |
|---|---:|---:|---:|
| ComfyUI PNG, 10 MiB IDAT plus workflow | 1.924 ms | 1.708 ms | -11.2% |
| Stealth PNG, 2048×2048 RGBA | 44.706 ms | 18.367 ms | -58.9% |
| Routine JPEG, 5 MiB with EXIF and scan after SOS | 1.480 ms | 1.403 ms | -5.2% |
| JPEG APP2-before-SOS stress case | 1.379 ms | 8.119 ms | +488.8% |
| PNG without metadata, many 4 KiB IDAT chunks | 10.599 ms | 9.530 ms | -10.1% |
| PNG without metadata, browser-canvas-style RGBA | 8.120 ms | 1.777 ms | -78.1% |
| PNG without metadata, one large photo-style IDAT | 13.965 ms | 2.000 ms | -85.7% |

The APP2-heavy row remains visible as a stress result and is not treated as the routine-path ±5% acceptance case. It demonstrates the expected extra cost of walking many SOS-preceding segments while preserving the FR-JPEG-01 and D-22 full-segment scan requirement.
